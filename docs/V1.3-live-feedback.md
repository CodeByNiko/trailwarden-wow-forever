# Wayfinder 1.3: cemetery routing and compact display

## Observed report and underlying causes

The supplied live screenshot shows The Night Watch ready for turn-in, The Totem of Infliction at level 25 with Skeleton Finger 7/10 (plus other incomplete items), and a quest-log counter of 29/40. The player is level 22.

Code review identified three relevant defects: the +2 comfort rule also excluded accepted quests, so a level-25 collection quest could disappear before scoring; capacity used a legacy global or 25 instead of the standard-quest client API; and nearby-work batching was a small scoring penalty within only 150 yards. The queue additionally represented each quest only once, omitting other unfinished objectives from that same quest. These mechanisms explain how known local work could be overlooked. The screenshot alone does not reveal every runtime provider result, so it cannot establish which combination fired in the original session.

## Route changes

- Comfort settings constrain new pickup recommendations. Accepted quests remain candidates and show ABOVE RANGE when appropriate. Known group/dungeon/PvP/raid policies still apply; completion does not come from arrival.
- The standard log limit comes from `C_QuestLog.GetMaxNumQuestsCanAccept`, with validated legacy fallback. A client limit of 40 and 29 active quests leaves eleven slots.
- Local batches use mapped, accepted, unfinished objectives within 450 direct-map yards. A hand-in, pickup or delivery is marked as leaving the batch when it is farther than both 120 yards and the local objective's distance plus 75 yards. Such a stop sorts behind current work, independently of its numerical score. A hand-in at the player's location remains usable.
- Explicit focus can override the batch. Skipped and level-deferred objectives cannot hold a batch open. A full log suppresses new accepts but does not force abandoning useful local objectives.
- Queue simulation advances from each preceding stop and tracks individual objective keys. It includes remaining local goals from the same quest, rather than assuming the whole quest was finished by its first objective. This is still a heuristic preview: future drops, accept decisions and unlocks are not predicted.

## Skip for now

An above-range **accepted** quest has a Skip for now button. Its quest level is saved per character, separately from the 15-minute skip. While out of range it is excluded from automatic navigation and appears as a Later entry in the bounded plan (up to four preview steps). If the preview is shortened, the status still reports saved-for-later quests. Settings can show all four preview rows. Long plans are not full quest trackers; Questie remains the full log.

The quest resumes automatically when player level plus the configured range reaches the quest level. For level 25 with a +2 range, that is player level 23. Expanding the range to +4 makes it eligible immediately. The deferral has no timer; click its Later entry to resume immediately or use `/wf undo`. Completed deferred quests become hand-ins; abandoned/completed records are cleaned up only when live progress is reliable. Restore skipped quests in settings also restores level deferrals.

## Display

The main frame is 360 units wide (previously 400). With two upcoming steps it is 462 units tall (previously 626); default panel scale is 90%. The preview supports 0/2/4 rows and a collapsed layout. The settings view temporarily expands for its controls.

The navigator is a transparent 130×88 frame with a 38-unit arrow, distance and quest caption. No border, background or header is created. Missing position/facing/connection states remain explicit. Text shadows improve contrast where supported. Dragging and position persistence remain.

Mouse wheel over the header changes panel scale; over the navigator changes arrow scale. Locked windows ignore wheel resizing. Settings and `/wf scale N` / `/wf arrowscale N` provide independent scales. Panel range is 60–130%, arrow range 60–150%. Existing custom scales are retained; the previous default 100% panel migrates to 90% once.

## Quality assurance

208 checks: 147 scenario/integration, 40 pure engine, 21 provider/client contract. Fifteen serialized decision frames replay successfully. Added regressions reproduce the report's level, quest levels, 7/10 item progress and completion sequence using synthetic provider data. They cover several item objectives, four concurrent local quests, full logs, hidden/skipped work, manual overrides, level/range resumption, profile separation, capacity API failure, wheel locks and independent display scales.

Synthetic spawn geometry is not a replay of the user's actual Forever database. Actual provider coverage, corpse/item drops and phase positions still need gameplay feedback. `/wf trace` and `/wf debug` remain available. Broader performance profiling (audit point 7) stays deferred.
