# Wayfinder 1.7.0: cave access and OpenMap guidance

The accepted live-test scope is **entrance-first guidance plus minimap/OpenMap markers**, with no additional navigation addon. This is an incremental response to the Lord Melenas/Fel Rock hillside problem. It does not claim universal pedestrian pathfinding or draw a continuous walking route.

## What changes in play

| Situation | Navigation behavior |
| --- | --- |
| Outside Fel Rock with Lord Melenas selected | Arrow/native waypoint target the entrance first; cyan marks entrance and gold marks final quest objective |
| Matching Forever entrance POI available | Prefer live client coordinates, checking linked cave map or localized cave name to guard against reused POI IDs |
| No matching live POI | Use a labeled Reference entrance; this fallback still needs confirmation in live Forever |
| Recognized cave map or matching indoor subzone | Stop unsupported tunnel bearings; consult cave layout and objective marker |
| Beside/above the cave in 2D | Proximity alone cannot advance the interior stage or complete a quest |
| Ordinary quest elsewhere, including Duskwood | Existing quest selection and direction guidance, with an objective marker |
| Death, pause, danger stop or unmapped goal | No actionable access/goal markers; existing safety and quest-truth behavior remains |

Access records cover Fel Rock, Shadowthread Cave and Ban'ethil Barrow Den. Cave footprint bounds help associate mapped targets with an access point; those artwork rectangles do not prove that an arbitrary target is underground or that an approach is walkable. Reference placements and access-stage recognition are the main live-test uncertainties.

## Display and controls

- Small cyan entrance and gold objective markers use HereBeDragons supplied by Questie. They follow minimap clipping/rotation and appear in OpenMap through its supported world-map integration.
- `/wf routepins` toggles the markers for this character. OpenMap's menu also offers Wayfinder access points. Core navigation does not require the marker toggle to be on.
- Real LibStub is a callable table; the integration uses its GetLibrary method. Missing map-library support fails gracefully and is reported in `/wf debug`. Temporary pin errors retry without a new quest event.
- Main panel and arrow keep their existing independent sizes and positions. The arrow caption identifies the entrance while the main card retains the quest name.
- Arrival at an entrance means enter the cave, not quest completed. Progress still comes from the actual quest log.

## Live test

1. Exit WoW, install the release's Wayfinder folder and restart. Keep QuestieDB, Questie and OpenMap enabled. No saved-variable deletion is needed.
2. Outside Fel Rock, select/continue Twisted Hatred. Check that the guide says to approach the entrance and that cyan/gold markers identify different locations. The source line distinguishes a live entrance POI from a reference.
3. Reach and enter the opening. Confirm entrance arrival wording, then cave-map guidance when the client reports the cave map/indoor subzone. No direct bearing through a tunnel wall should remain.
4. Complete and turn in the quest normally; confirm progression from real quest updates. Moving near a marker must not complete it.
5. On the Dwarf Shaman in Duskwood, confirm normal nearby quest batches, turn-ins and combat limits still behave as before.
6. Try minimap zoom/rotation, OpenMap zoom, `/wf routepins`, and pause/resume. For unexpected behavior, copy `/wf debug` and provide player coordinates plus the visible entrance/objective.

A successful synthetic test is not a confirmed cave walk. No live success is claimed before the user's test.

## Limits and subsequent terrain work

OpenMap publishes map display APIs, cave-art bounds and boat/zeppelin routes. It does not expose a pedestrian network. Drawing a line between arbitrary spawn coordinates would repeat the original failure.

The entrance arrow is still direction guidance, not a verified approach corridor. Inside caves, use OpenMap's cave layout. Known combat-target level checks do not establish that every point along a journey is safe. Unknown access areas, floors, bridges and transport schedules retain the existing limitations.

A later full walking-route implementation needs a validated Forever traversal dataset, explicit surface/cave/floor connections, a graph search that cannot attach across walls merely by nearest 2D proximity, and rendering of only supported path sections. Begin with Teldrassil and Duskwood. Keep waypoint progression separate from quest completion and avoid recalculating the regional quest plan after every kill.

## Validation

`python3 tools/check.py`: **368 checks and 37 replay frames**. Access/map tests cover the live POI contract, fallback, coordinate transform, cave evidence, preserved quest-giver arrival wording, callable-table LibStub, HBD method signatures, owner-scoped cleanup, pooled marker updates and transient-error recovery. Other suites retain questing, XP and combat-safety regressions.

Development frame renders support layout review only. The release package checks TOC files, original arrow asset, ZIP CRCs and a single Wayfinder/ root. Identical inputs produce byte-identical archives.
