# Wayfinder 1.5: stability before theoretical throughput

## Evidence from live feedback

The screenshots show the same level-22 character in Duskwood alternating between The Totem of Infliction and Howling in the Hills in Redridge, plus the generic planner-exception card. The projected rates vary substantially while measured XP/hour changes much less. The precise thrown Lua exception is not visible in the screenshots, so this review does not claim a particular runtime line was proven to fail.

The code did reveal two structural causes: every XP/kill event scheduled a full capture/plan, including forecasts, and forecast/learning exceptions shared the same failure boundary as quest guidance. Additionally, XP utility removed the old zone-distance preference after including one-way cycle travel, while no regional commitment existed. Small sample/confidence changes could therefore change the winning zone. This was a poor fit for stable questing, even when each individual arithmetic calculation was valid.

## Why not plan once per level or per level range?

A fixed level plan reacts too slowly to accepted/completed quests, unlocks, skipped work and actual movement. Planning everything on every kill reacts too quickly to noisy estimates and frequent events. The implementation now has separate lifecycles:

| Layer | Updates | Responsibility |
| --- | --- | --- |
| Measurement | XP bar/events, approximately one-second sampling | Measured XP/hour, remaining XP, ETA and pace observations |
| Quest step | Coalesced meaningful quest changes | Advance an accepted/completed/turned-in/skipped objective promptly |
| Forecast | Cached for 45 seconds unless inputs materially change | Re-estimate remaining cycle value without recomputing all learning/models for each kill |
| Regional journey | Start, local exhaustion, deliberate physical zone change, manual replan | Keep useful work together and avoid Duskwood/Redridge oscillation |

Level-up is a meaningful eligibility change, not a command to abandon the region. The guide continues to use the current Forever provider for new and existing quests.

## Continuity rules

A new plan prefers mapped work in the player's current region. A committed region remains preferred while it has actionable candidates. An unfinished selected objective stays selected on automatic updates, and partial progress does not move the pointer to another spawn of that same objective while the current work area remains relevant. Its key must still exist in newly collected live candidates: completion, removal, skip, level deferral, policy changes or unavailable targets can release it immediately.

When the region has no remaining viable steps, the planner can move onward. Deliberately entering a different quest region with local work adapts the commitment to actual location. Manual focus can choose another region. **Auto route** removes manual focus without discarding regional continuity. **Replan region now** in settings or `/wf refresh` explicitly releases the commitment and evaluates wider alternatives.

The queue prefers remaining local work before foreign-zone steps. The regional commitment is captured in deterministic replay and scoped to the current character. It is session state, not a permanently locked guide.

## Event and forecast policy

XP and rewarded-kill events update measurement, but do not schedule a complete route plan until a periodic review is due outside combat. Quest events coalesce for 0.5 seconds. Identical quest-log snapshots within 60 seconds do not rebuild the plan. A changed objective count still refreshes live quest state promptly. Idle maintenance is once per minute; movement refreshes require approximately 120 yards and at least ten seconds since planning. Death/resurrection still invalidates navigation promptly.

Forecast caching keys include the character, progress revision/level, catalog generation, eligible step keys, comfort level and active skip/defer state. Goal completion/removal changes the key immediately. Otherwise models are reused for up to 45 seconds; moving approximately 300 yards also invalidates the cache. Cached models can be projected from the current origin without rebuilding all cost/learning data. A source failure clears the failed forecast rather than poisoning it as permanent absence.

These intervals are conservative UX defaults, not a claim of mathematically optimal timing. Future real-session traces can tune them. Existing current-step/batch constraints remain more important than a small modeled rate advantage.

## Failure behavior

- XP event processing is isolated from actual quest event processing, so a measurement exception cannot prevent recording a turn-in.
- XP sampling/learning failures do not invalidate the live quest log. The measured display can be unavailable while quest guidance remains usable.
- Forecast failure removes optional economic models and uses normal quest routing. One failed quest target can be deferred without discarding all other candidates.
- A core planning exception may retain a previous active step only when its exact key is independently rediscovered against the freshly captured live log. A completed objective cannot survive this validation. If no safe step can be confirmed, the guide still fails closed instead of inventing navigation.
- Diagnostics include forecast/learning/target failures, region commitment and forecast build/cache counters. Screenshots without diagnostics cannot identify every provider/client exception; actual live verification remains necessary.

## Display

The former small inline XP text is replaced by two labeled columns: EXPERIENCE / HOUR and NEXT LEVEL, with 16-unit values and a quiet divider. Measured values have thousands separators. The current zone is visible in the step heading. Low-confidence quest/grind projections are in the hover details, alongside confidence and session information, rather than competing with navigation text.

The metric section has its own bounds in full and compact layouts. Compact height is 374 frame units; the default two-row expanded height is 526. Scaling remains independent of the transparent navigator. Development previews are generated from actual frame calls and synthetic data, not in-game screenshots.

## Validation and external references

291 checks pass: 165 integration/scenario, 49 pure engine, 21 provider/client contracts and 56 experience. Thirty-six replay frames include twenty consecutive kills with strongly alternating Duskwood/Redridge XP estimates and a level-up, without changing region. Regression checks also cover duplicate XP/log bursts, immediate meaningful progress, independent sample/learning/forecast failures, cached partial-kill forecasts, safe recovery and completed-objective invalidation.

The implementation is an original adaptive planner. External references support the architectural distinction, rather than validate our precise thresholds:

- [Warcraft Wiki: QUEST_LOG_UPDATE](https://warcraft.wiki.gg/wiki/Event:QUEST_LOG_UPDATE) documents that the event can fire frequently for reasons beyond meaningful objective progress.
- [RestedXP custom-guide documentation](https://community.restedxp.com/custom-guides/) illustrates an explicit step/guide approach. No paid guide data or proprietary route has been copied, and this review does not claim to know competitors' private algorithms.

This release deliberately favors completing coherent regional work over repeatedly chasing a theoretical instantaneous XP maximum. It does not solve terrain/transport travel or every future chain globally. All automated fixtures remain synthetic; the user's live play will establish remaining Forever-specific behavior.
