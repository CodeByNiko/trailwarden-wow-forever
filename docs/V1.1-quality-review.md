# Wayfinder 1.1 quality review

This pass concentrates on correctness, calmer navigation, less repeated work and clearer controls. It preserves the character-aware routing scope of 1.0 rather than inventing new route data before gameplay feedback.

| Finding | Change | Verification |
| --- | --- | --- |
| A short creature name could match a longer creature's completed objective | Match the most specific known name, with type-local ordering only when no semantic match is available | Reversed Wolf / Dire Wolf rows |
| Item routing said collect without explaining the source | Show buy/search/defeat instructions from the selected source, without changing cached entity data | Vendor, object and creature source scenarios |
| Arrival changed at a single sharp radius | Separate entry/exit thresholds per character and step | Enter, small jitter, leave area |
| Missing facing could hide the arrow while still claiming to guide | Explicit Facing unavailable state | Missing-facing regression |
| Degenerate map conversions could imply an incorrect zero distance | Validate finite coordinates, consistent world IDs and a non-degenerate map basis; retry transient failures | Invalid, degenerate and recovered transforms |
| A rejected replacement could leave an older owned map pin behind | Clear the stale owned marker and retain a diagnostic status | Rejected-set scenario and user-waypoint preservation |
| Full planning ran every two seconds while standing still | Replan on quest events, movement of about 35 yards, map/death changes, or periodic 15-second maintenance | Count actual planner executions across idle, movement and events |
| Optional module imports were repeated on hot paths | Reuse successful imports; do not cache unavailable modules | Retry and import-count tests |
| Resume route could leave the planner paused | Resume explicitly and return to automatic selection | Actual button callback |
| Skips had no visible immediate undo | Add Undo skip above the plan, and clear expired undo state | Actual click/visibility checks |
| Empty queues and long text gave poor feedback | Empty-list copy and bounded, shrinking current titles | Frame-state checks and development renders |
| Accidental drags could move the guide or arrow | Per-character window lock and mouse pass-through for the locked navigator | Locked/unlocked drag callbacks |
| Recovered errors looked like current failures | Separate current and recovered diagnostics | Injected failure followed by a successful plan |

All 93 local scenarios pass, including the previous 59. Release publication is gated by the same suite under Lua 5.1 and package validation in GitHub Actions. Development renders are generated from the frame calls, with synthetic quest data and substitute fonts. They do not replace live-client confirmation.
