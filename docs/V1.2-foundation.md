## Routing quality contract

The planner prioritizes useful, coherent questing from current progress rather than speed-leveling. Scores combine direct map distance, action preference, nearby clusters, zone changes, class relevance, log capacity and unfinished local work. Turn-in preference is full within 250 yards and fades to zero at 1,000. With at least three free slots, an unfinished objective within 150 yards adds a 450-point penalty to leaving for a turn-in farther than 150 yards. A full log can prioritize hand-ins instead. These are transparent heuristic weights, not measured optimal travel times.

The pure journey fixtures cover Darkshire arrival, a ready turn-in, successive accepts and objectives; and a separate level-7 Night Elf Warrior's Teldrassil accept/objective progression. They assert specific expected steps, stable choices and explicit progress transitions. They do not contain or claim a complete handcrafted guide for either zone.

## Data boundaries

The client reports shown quest-log entries and total quests separately. A mismatch is treated as an incomplete log; Wayfinder never expands or collapses the user's headers. Expand headers and refresh if necessary. Client objectives may be absent while loading and need not contain an objective ID. QuestieDB successful values are cached, but failures and missing support mappings remain recoverable. Provider map-support strings are trusted dependency code, as in its documented loader contract.

Observation coordinates represent the player's interaction area, not an exact NPC location. The arrow remains a directional guide, without terrain, cave-floor or transport pathfinding. All route inputs can be incomplete when upstream quest/phase data is incomplete.

## Local evidence and replay

Run `/wf trace`, select all and copy the JSON into a local file before reloading or logging out. The in-memory ring retains at most 20 decision frames and coalesces repetitive movement/maintenance frames. Nothing is uploaded automatically. Player names/GUIDs and display preferences are removed; quest progress, location and provider metadata remain, so inspect the export before sharing it.

For development, `python3 tools/replay.py path/to/export.json` replays expected route, queue and focus effects through the pure selector. Captured facts include query results, candidate targets, eligibility reasons, score weights, progress and expected decisions. Replay verifies the captured model; it does not emulate the full client or re-run every original provider API. Real gameplay traces have not yet been collected. The checked fixtures are explicitly synthetic.

Run `python3 tools/check.py` for all release checks. The release pipeline repeats them under Lua 5.1 and packages only addon runtime files. The first live session still needs to establish actual Forever coverage, event timing and positional correctness.
